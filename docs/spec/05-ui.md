# TransitGen Specification — 05 UI / UX

## 1. Window
- Default **960 × 600** logical px. Resizable 75–200 % in fixed steps (75/100/125/150/200), remembered per instance and as a global default.
- JUCE `Component` rendering, vector only (no bitmaps), so it scales cleanly. Repaint the playhead/plan view at 30 fps from a `Timer`; everything else repaints on change only.
- Dark theme only in v1. Colour tokens are defined once in `plugin/ui/Theme.h`.

## 3. Components and behaviour
| Component | Behaviour |
|---|---|
| **Plan view** | Shows the plan that the *next* fill will play: generated on the message thread from current settings (for Per-Phrase it shows the next phrase's seed). During a fill it shows the playing plan (from telemetry) with a moving playhead. Lanes: Source (one colour + icon per type: Pass = empty, Stutter = ▮▮ with slice lines, Reverse = ◀, TapeStop = ↘, TapeStart = ↗, Silence = hatched), Gate (step blocks), Crush (stepped shading), Filter (line). Hovering an event shows a tooltip with its parameters. |
| **Energy curve editor** | Overlaid on the plan view. Click empty space to add a point (max 16), drag to move, double-click to delete, Alt-drag on a segment to bend it (curve −1..1). Shift snaps t to the style grid. The first and last points move only vertically. Every edit is an undoable action, and the plan view regenerates live (< 1 frame). |
| **Curve presets** | Dropdown with the 8 presets from 03 §4, plus Flip H, Flip V and Clear (reset to Flat). |
| **Trigger panel** | Shows only the controls for the active mode. "Next fill in" counts down (Auto-Phrase) or shows "waiting for trigger / MIDI". **Preview** fires a one-shot fill at the next quantize point (needs the transport playing, or the free-running clock). |
| **Knobs** | Drag vertically (Shift = fine), double-click = default, right-click = type a value or MIDI-learn (v1.x). Show a value on hover. |
| **Seed bar** | Typing a number sets the seed. Re-roll and history ◀ ▶ behave per 03 §7. Lock dims Re-roll and forces Variation = Fixed (the dropdown shows "Fixed (locked)"). |
| **Header** | Preset browser (06), undo/redo, A/B compare (two full state slots), settings ⚙ (UI scale, show tooltips, check for updates, about/licence). |
| **Meter** | Output peak meter; shows a "FILL" badge while a fill is active. |

## 4. Interaction rules
1. Every control has a tooltip (it can be turned off).
2. Keyboard: Space = preview, R = re-roll, L = lock, Ctrl/Cmd+Z/Y = undo/redo, ←/→ = seed history.
3. Never block the UI on audio: all reads come from telemetry atomics (01 §7).
4. **Accessibility:** event types are distinguished by icon/pattern as well as colour (colour-blind safe), there is a focus ring for keyboard navigation, and JUCE accessibility handlers are set on all controls.
5. The **empty state** (transport stopped): the plan view still shows the generated plan. The countdown reads "Press play in your DAW".

## 6. Acceptance
- The plan view updates within 16 ms of any knob or curve change.
- The UI uses < 3 % of one core when idle and < 6 % during a fill at 30 fps.
- Every control is reachable and operable by keyboard.
